### New tests

1. Coverage credits real elapsed time despite timer drift.
2. Coverage excludes stalls, suspends and clock adjustments in either direction.
3. Samples, details and events commit as one batch, and a rejected batch stores nothing.
4. An exhaustion review unblocks only the events that were reviewed; a later event blocks again.
5. A clock correction of the boot time is not treated as a restart; a real restart still verifies.

Two existing tests were adjusted to the new rules: confirmations in fixtures now carry recorded heavy seconds, and the failed-verification test moves the boot time by 100 seconds instead of one.

## Not validated — do not treat as tested

- **Installing 1.1.1.** Updating the service needs an administrator approval that only the owner can give. Until then the fixes are not running, and their effect on real gap counts is unmeasured.
- **Page-file resize, relocation, restart verification and offline restoration.** `Get-VM` returned "You do not have the required permission to complete this task" again. The session runs without elevation and the account is not in Hyper-V Administrators. The transaction tests still use a simulated backend. `docs/VM-ACCEPTANCE.md` has not been executed.
- **The restart-detection change on real Windows.** It is covered by a simulated-backend test only. It belongs in the VM run (item 9 of the checklist was extended).
- **Sustained disk contention.** The sampling fix could not be reproduced on demand.
- **Lemon Squeezy checkout and live licensing.** `commerce.json` has zero IDs; no network licence call was made.
- **Recommendation readiness.** Blocked, correctly, by: no marked light/normal/heavy sessions, the unreviewed exhaustion events, and (after updating) the heavy confirmation that must be given again once real heavy sessions exist.
- Overnight overhead, real disk-full handling, sleep/resume behaviour and non-English Windows.
